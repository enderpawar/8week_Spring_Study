## 해결 기록

<!-- 해결한 부채는 위 표에서 지우지 말고 상태를 '해결(DayNN)'로 바꾼 뒤 이 절에 한 줄 요약을 남긴다. -->

- Day07 — 기존 ID 저장은 교체하고, 없는 예약은 `Optional`과 `ReservationNotFoundException`으로 바꿨다. Service 단위 테스트로 중복 미발생과 없는 ID 예외를 확인했다.
- Day07 — 404 응답과 500 내부 메시지 비노출을 예외 처리기 단위 테스트로 확인했다.
- Day07 — MockMvc로 예약 200, DTO 검증 400, 없는 예약 404, 경로 ID 검증 400의 MVC 계약을 확인했다.
- Day10 — `JpaReservationRepository`를 유일한 `@Repository` Bean으로 전환하고(`InMemoryReservationRepository`의 `@Repository`는 주석 처리) H2+Flyway로 영속화를 확인했다. 재시작 시 데이터가 사라지는 문제는 해소됐다(단, `spring.datasource.url`이 인메모리 H2라 JVM 프로세스 종료 시에는 여전히 사라진다 — 이건 별개로 "DB 서버가 파일/외부 DB인가"의 문제이며 이 트랙 범위 밖).
- Day14 — `V2__add_name_check_constraints.sql`로 `room_name`·`requester_name`에 `CHECK (... <> '')` 제약을 추가했다(`V1`은 손대지 않음). `entityManager.createNativeQuery()`로 Bean Validation을 우회한 직접 INSERT 테스트로, 빈 문자열이 이제 `PersistenceException`으로 거부됨을 확인했다.
