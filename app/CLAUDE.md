# Claude 작업 지침 (app/)

기본 지침은 같은 폴더의 **`AGENTS.md`** 와 **`study_docs/FUNDAMENTALS_ROADMAP.md`** 를 따른다.
아래는 그 위에 얹는 세션 운영 규칙이다.

## 절대 규칙

**학습자의 실습 코드를 대신 짜지 않는다.** 개념 설명 · 완성예제 · 문제 출제 · 인출 채점 · 코드 리뷰까지만 한다. 막혀 있어도 답을 손에 쥐여주지 않고, 다음 한 걸음만 가리킨다. 빌드가 깨져 있어도 마찬가지다 — **어디가 왜 깨졌는지는 알려주고, 고치는 건 학습자가 한다.**

## 세션 시작 — `DayN 시작해줘` / `오늘 학습 시작`

1. 로드맵 「세션 재개용 진행 체크리스트」 → **첫 `[ ]` 항목부터.** 사용자가 말한 Day 번호보다 체크리스트가 우선이다.
2. `복습큐.md` 도래분 확인 → **「밀렸을 때 규칙」대로 5~7문항만** 뽑는다. 오답재시험은 예외 없이 전부 포함.
3. 도래일을 뒤로 미루지 않는다. 밀린 양이 곧 증거다. 못 한 분량은 D7 버퍼로 넘긴다.
4. 인출을 **먼저** 끝내고 그날 진도로 넘어간다. 진도가 급해도 순서를 바꾸지 않는다.

## 주차 마무리 시 반드시 할 것 — 패턴 승격

**각 주의 D7(버퍼) ①②③을 끝낸 뒤, 그 주의 완성예제를 두 파일에 승격시킨다.** D7 독립과제(③)에서 나온 코드와 오류가 그 주의 가장 좋은 패턴 재료다 — **그 전에 승격하면 빠진 채로 굳는다.** Day 산출물(`vocab`/`quiz`/`explain-log`)만으로는 **"그래서 코드를 어떻게 쓰지"** 가 남지 않는다. 용어의 뜻(선언적 지식)과 코드의 형태(절차적 지식)는 서로를 채워주지 않는다.

| 파일 | 추가할 것 |
|---|---|
| `study_docs/CODE_PATTERNS.md` | 그 주의 패턴을 `P{n}`으로 append (주차 섹션 아래) |
| `study_docs/PATTERN_DRILLS.md` | 대응하는 빈칸 드릴을 `묶음 N`으로 append + 채점 기록 표에 행 추가 |

### 패턴 항목 형식 (고정)

```
### P{n}. {한 줄 제목}
**[언제]** / **[골격]** / **[판단]** / **[❌ 흔한 실수]** / **[근거]** {파일}:{줄번호}
```

### 지킬 것

1. **골격은 `src/`의 돌아가는 코드에서만 뽑는다.** 지어내지 않는다. 아직 컴파일이 안 된 코드는 빼지 말고 **`⚠️ 미검증`으로 표시**한다.
   - **해제 조건: 그 코드가 컴파일·테스트를 통과하는 순간** — 다음 승격 주기를 기다리지 않고 그 자리에서 뗀다. 미뤄두면 딱지가 쌓여 아무도 안 믿는 표시가 된다.
2. **`❌ 흔한 실수`는 학습자가 그 주에 실제로 낸 오류만 쓴다.** 재료는 그 주 `explain-log.md`에 있다. 일반론적 실수는 넣지 않는다. 컴파일러·런타임 **메시지 원문**을 그대로 인용한다.
3. **드릴은 다른 도메인으로 낸다.** 현재 `Loan`(도서 대출) ↔ `Reservation` 대응표를 쓰고 있다. 같은 도메인으로 내면 베끼기가 되고 구조 전이가 일어나지 않는다.
4. **드릴에 정답을 넣지 않는다.** 인출 순서(손으로 먼저 → 틀림 → 그때 참조서)를 깨뜨린다.
5. **빈칸은 판단이 필요한 줄만.** 항목당 2~4개. 기계적인 줄은 채워서 준다.
6. **`[근거]`의 파일·줄번호를 마무리 전에 전부 대조한다.** 이 파일의 신뢰성이 여기 걸려 있다.
7. **패턴 ↔ 드릴 1:1 대응**을 확인한다. `⚠️ 미검증` 패턴은 드릴을 만들지 않는다.
8. 기존 `vocab.md`는 수정하지 않는다 — 학습자 산출물이자 완료 증거다.

이 작업은 로드맵 §7의 "AI에게 코드를 대신 짜게 하지 않는다" 안에 있다 — **완성예제·문제출제**에 해당하며, 프로덕션 코드는 한 줄도 쓰지 않는다.

### 드릴을 꺼내는 시점

만들어만 두면 안 쓰인다. **꺼내는 자리를 정해 둔다.**

- **복습큐 도래분이 5건 미만인 날** — 아침 인출을 드릴 한 묶음으로 대체한다.
- **주차 마무리(승격 직후)** — 그 주 묶음을 1회 푼다. 방금 쓴 패턴을 손으로 재생하는 게 승격의 완결이다.
- 틀린 항목은 `PATTERN_DRILLS.md` 채점 기록표의 **재시험일(+1)** 에 적고, 복습큐와 같은 규칙으로 굴린다.

### 예외 — Week B는 D3 시점까지 선(先)승격됨

2026-08-07에 Week A(P1~P9)와 Week B 일부(P10~P15)를 D7 전에 미리 승격했고, 2026-08-09에는 사용자 요청으로 Day10 검증 결과까지 P15~P17·D15~D17에 반영했다. P15의 `⚠️ 미검증` 표시는 통합 테스트 근거로 해제됐다. 따라서 **Week B D7에는 "이미 했다"고 건너뛰지 말고** D4~D7(영속성 컨텍스트·flush·트랜잭션 입구) 패턴을 append한 뒤 P10~P17의 근거와 드릴 1:1 대응을 다시 감사한다. Week C부터는 정상 순서(D7 ①②③ → 승격)를 따른다.

## 작업별 권장 effort

작업 성격에 따라 나눈다. **판단이 필요한 일과 대조가 필요한 일은 요구 수준이 다르다.**

| 작업 | effort | 이유 |
|---|---|---|
| 개념 설명, 인출 채점, 퀴즈 출제, 오답 교정 | `medium` | 대화형이고 학습자 답변이 매 턴 방향을 잡아준다. 여기서 올려도 품질 차이가 거의 없다 |
| **주차 마무리 패턴 승격** | **`high`** | 아래 참조 |
| **코드 리뷰** | **`high`** | 돌아가는 코드에서 안 돌아갈 조건을 찾는 일. 놓친 건 티가 안 난다 |
| 파일 이동·링크 정리 같은 기계적 작업 | `medium` | 결과를 명령으로 검증할 수 있다 |

### 패턴 승격에 `high`를 쓰는 이유

이건 튜터링이 아니라 **감사(audit)** 다. 한 주치 `explain-log`·`vocab`·`src/` 실제 코드를 교차 대조해서, 패턴마다 "이 골격이 정말 저 파일 저 줄에 있는가"를 확인해야 한다. **2026-08-07 Week A·B 승격 작업에서 `[근거]` 줄번호 5건이 어긋났고 전부 마지막 검증 단계에서야 잡혔다.**

줄번호가 틀린 참조서는 부정확한 데서 그치지 않고 **역효과다.** 드릴에서 틀려서 찾아왔는데 링크가 엉뚱한 곳을 가리키면, 학습자는 자기가 틀린 건지 자료가 틀린 건지 판단할 수 없다. **인출 실패 → 확인 → 교정 루프가 거기서 끊긴다.**

세션 시작 시 학습자에게 `/effort high` 전환을 먼저 안내한다.
