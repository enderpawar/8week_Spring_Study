1. **비계 점감**: 개념마다 완성예제 → 빈칸 채우기 → 독립 구현으로 도움을 뺀다. (초보자에게 "직접 재현부터"는 금지.)

3. **CS 연결**: 모든 개념을 이미 아는 CS 이론에 붙인다(트랜잭션=ACID, 인덱스=B-tree, 해시=BCrypt…). 이게 한 달을 가능하게 하는 지렛대.

## 1. 학습 단위: 티어링된 유닛

개념 난도에 따라 두 종류. **용어까지 6단계를 강제하지 않는다.**

### Full 루프 (메커니즘/하드 개념 — DI, 트랜잭션, 영속성 컨텍스트, 프록시, JWT 등)
1. **개념 + 완성예제** — AI가 CS에 연결해 설명 + 주석 달린 도는 코드. 학습자는 타이핑·실행.
2. **빈칸 예제** — 핵심 2~4줄을 비우고 채움.
3. **독립 변형** — 살짝 다른 요구로 혼자 구현. (근접전이)
4. **인출** — 코드/노트 덮고 재작성 + 퀴즈 → **정답 대조 → 오답 교정**(틀린 건 오개념 강화 방지).
5. **예측→실행→차이설명** — "이 SQL/동작이 어떻게 나갈지" 먼저 예측 → 실행 → 예측과 실제 차이를 설명. (한 문단 자기설명보다 강함)
6. **복습큐 등록** — 인출 질문을 `복습큐.md`에 +2/+7/+14일 일정으로 넣음.

### Light 루프 (용어/작은 개념 — 상태코드, 매핑 애노테이션 등)
- 개념 + 짧은 예제 → 인출 1문항 → 복습큐 등록. (완성·빈칸 생략)

## 5. 졸업 루브릭 (8/20~21, 코드·노트 없이 말로 설명)

- [ ] 요청 하나가 계층을 어떻게 흐르는가 / HTTP 메서드·상태코드 계약
- [ ] DTO를 왜 분리하나 / **Validation과 전역 오류 처리 흐름**
- [ ] DI를 쓰는 이유 3가지 / 생성자 주입인 이유 / 싱글톤 무상태 원칙
- [ ] `@Transactional`이 프록시로 도는 의미 / **self-invocation 한계**
- [ ] 영속성 컨텍스트가 `save()` 없이 UPDATE 하는 원리 / LAZY 프록시 초기화 시점
- [ ] N+1이 왜 생기고 어떻게 없앴는지(숫자로)
- [ ] **Flyway로 스키마를 재현**하는 이유 / DB Constraint와 앱 검증의 역할 차이
- [ ] JWT stateless 장점과 로그아웃 무효화 문제 / 401 vs 403
- [ ] Unit/Slice/Integration을 각각 언제 쓰나 / 무엇을 mock하나
- [ ] **로그로 버그를 추적**하는 절차 / 민감정보를 안 남기는 이유

## 7. 규칙

- AI에게 **코드를 대신 짜게 하지 않는다.** 개념설명·완성예제·문제출제·인출채점·코드리뷰만. 피드백은 AI 의견이 아니라 **실제 코드·테스트·공식문서**에 근거.
- 밀리면 자르는 순서: 8/19 실배포 → 버퍼 미화 → Docker/CI. **JPA·트랜잭션·검증·오류처리·인증·테스트·디버깅은 안 자른다.**
- `record`는 DTO에만. Entity/가변 Domain에 쓰지 않는다.
- 기존 프로젝트가 Boot 3면 학습 중 Boot 4로 업그레이드하지 않는다(잡음).
- `archive/`는 읽기 전용. 실습은 `app/`.
